## 按顺序完成

### B1：真实网络学堂连接与课程文件

参考 [OneTHU 源码核对](OneTHU参考与课程知识库方案.md)：LearnClient 的学期、课程、文件列表与带 CSRF 的下载。其 Tauri 下载与桌面登录依赖需要适配，不能只 import core 就宣称可登录。

- 优先证明本人本地登录 → 真实学期／课程／文件目录 → 一份有效 PDF 下载。学校登录与二次认证由账号本人完成，模型不参与认证。
- 实现本机连接页 `/api/learn/connect` 与连接状态；认证实现封装在你负责的后端或辅助进程内，A 不接触密码、Cookie、学校协议。
- 校验下载响应确为有效文件；登录 HTML、无权限、过期、限流和结构变化明确报错。
- 加批次串行导入和逐项状态；下载字节直接进入现有 upload/解析服务，产出真实 materialId/versionId，不能要求用户下载后再手动上传。
- 持久化学期／上游课程／文件身份、本机 courseId、内容摘要与材料版本映射；同源同内容去重；内容变化不覆盖旧材料。目录达到数量上限时提示不完整。
- 重试只处理失败／待认证项；重启恢复完成项和待执行项，学校会话可要求重新登录。

### B2：课程知识库和多材料问答

- 课程身份使用本地稳定 courseId 映射学期＋上游课程 ID，避免同名／跨学期混淆；只对该课程已就绪材料检索。
- 复用逐页解析，片段 ID 包含材料／版本；持久化关联和可重建检索数据。
- 小范围在预算内可使用完整上下文；超预算采用 SQLite FTS 或轻量词法检索，中文分词／字符策略必须经中文问题验证；控制片段总预算。
- 课程问答沿用真实模型与引用校验，selectedScope 为本次材料版本集合。引用映射真实文件和页序，检查课程归属及逐字摘录；无证据明确不足。
- 保留现有单材料问答、手动上传、原文件接口、状态与导出能力；新课程 API 不破坏已有路径。

### B3：状态与白板存储

- `/api/state` 保留 revision 原子保存，返回完整新状态；新增 activeCourseId 和卡片 courseId，并兼容历史记录字段缺失迁移。
- 保留正文变化强制待复习、来源校验、服务端时间戳、冲突错误和重启恢复。
- 每课程独立白板读写：revision、nodes、edges。节点只引用本课程已保存卡片；坐标必须为有限数值，ID 唯一，边端点存在。
- 白板正文不重复存储；移除节点不删除卡片；独立事务／版本冲突防止旧写入覆盖新状态。
- 持久化课程材料与白板数据；后端重启后能读回。你不负责画布组件、拖动手势或视觉样式。

## B 自己验收

通过真实 HTTP／服务测试完成，不依赖 A 页面：

- 本人真实学校会话、一门课的目录、至少两份支持 PDF 自动入库；核对原件和页数。
- 重复导入无重复材料、单项失败重试、登录失效暂停和重连继续；坏文件／登录 HTML 明确失败。
- 一个需综合两份同课材料的问题，来源映射正确；另一课程不进入范围；材料不足不造引用。
- HTTP 创建／编辑／复习卡片，保存三节点两条线的白板；拒绝错误 revision、无效 cardId 和非法边端点。
- 停服务再启动：课程映射、导入结果、PDF、学习状态、白板位置与线均恢复。
- 原后端测试通过；真实模型与学校访问记录分别写明，不用测试桩代替。
