## 3. 首次安装实际出现的依赖告警

在新包解压目录执行 `npm ci` 成功，但随后 `npm audit --json` 返回4个受影响依赖记录：`pdfjs-dist`（high）、`vitest`（critical）、`tinypool`（critical）、`@vitest/mocker`（moderate）。后3项属于测试工具链，不能直接表述为运行时前端存在同等可利用性。运行时 PDF 组件告警与恶意 PDF 相关，评委评估优先使用包内自制材料。

对应公告：[PDF.js](https://github.com/advisories/GHSA-hq66-cqwq-w95j)、[Vitest mocker](https://github.com/advisories/GHSA-82fw-gwwq-j7x9)、[Tinypool 1](https://github.com/advisories/GHSA-5gmw-xhrv-c9v3)、[Tinypool 2](https://github.com/advisories/GHSA-85c8-ppgw-ccpr)。这表示锁文件命中了公告范围，并不证明本应用已可被实际利用；本轮没有进行利用验证。建议升级 PDF.js 并同步验证本地 worker、资源复制和阅读器；Vitest 的建议修复涉及主版本升级，需另行回归。没有自动执行 `npm audit fix --force`。

## 4. 给评委的最短验证路径

1. 解压 **v3** 到普通可写目录，进入含 `backend/`、`frontend/` 的项目根目录。执行 `python --version`（macOS 可用 `python3`）与 `node --version`，确认满足要求。
2. 按根 README 创建 Python 虚拟环境，安装 `backend/requirements.txt`。不配置模型也可启动 `python -m backend`；打开 `http://127.0.0.1:8000/api/health`，区分“服务已运行”和 `modelConfigured`。
3. 第二个终端进入 `frontend/`，执行 `npm ci`、`npm run dev`，打开 `http://127.0.0.1:5173/#home`。进入学习空间，先上传包内自制 PDF，验证渲染、翻页、手写卡片、保存、导出和重启恢复。
4. 将 `backend/.env.example` 复制为 `backend/.env`，本机填写允许的平台配置，重启后端。`python -m backend --check-config` 只检查完整性；`--list-models` 只辅助找模型，不替代真实请求。用自制 PDF 提问“线性系统需要满足什么条件？”，检查真实回答、页数与出处。
5. 有学校账号并需评估课程导入时，安装 Playwright Chromium（或按系统配置已装浏览器），打开连接页，再点击“打开学校登录窗口”。本人完成认证并进入课程列表，保留窗口，再验证连接、返回前端刷新。选择课程与少量文本 PDF 导入，随后评估课程问答和 AI 白板。
6. 无学校账号就记录课程导入／课程白板“外部条件不具备”；无模型凭据就记录 AI 功能“外部条件不具备”。首页示意和接口桩都不能替代真实能力评估。

模型常见失败：401／403检查凭据与模型权限；404核对地址、模型名与协议；429检查额度或并发；`MODEL_INVALID_JSON` 检查结构化输出兼容性；超时检查网络与上游服务。不要把密钥写在截图、故障报告或提交文档中。
